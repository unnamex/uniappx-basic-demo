# MPM 离线工艺预览系统 — 项目亮点与研究方向

> **项目名称**：avpbc-pop（MPM 离线工艺预览系统）
> **技术栈**：uni-app x + UTS + Vue 3
> **目标平台**：Android / HarmonyOS NEXT / Web
> **定位**：面向航空航天等高端制造业的车间现场离线工艺指导终端

---

## 一、项目概述

本系统是公司 **MPM（制造过程管理）系统** 的移动端延伸，为一线操作人员提供在 **无网络环境** 下查看完整工艺规程、操作步骤、CAD 图纸和多媒体指导的能力。

系统通过导入由 MPM 系统导出的 `.srd` 离线数据包，在本地完成工艺数据的解密、解压、解析与持久化存储，实现完全脱离后台服务器的独立运行。其中，数据包内的 UI 布局配置（Tab 分组、页签、组件类型及排列方式）由公司自研的 **ASP+ 平台** 统一配置后随数据包一并导出，实现了"一次配置、多端呈现"的标准化交付能力。

---

## 二、核心业务亮点

### 2.1 纯血鸿蒙端离线 CAD 预览 — 填补行业空白

这是本项目最核心的业务突破。当前主流工业软件的 CAD 预览方案均存在明显局限：

| 维度 | 主流工业软件方案 | 本项目方案 |
|------|---------------|----------|
| **CAD 预览** | 服务端渲染 / PC 专用软件（JT2Go、Creo View 等） | 终端本地 `web-view` 渲染 HTML 封装 CAD |
| **网络依赖** | 必须在线连接 PLM/MES 服务器 | 完全离线，`.srd` 数据包一次性导入 |
| **鸿蒙支持** | 无（Siemens、PTC、达索均未适配 HarmonyOS） | ✅ 在 HarmonyOS NEXT 上完整运行 |
| **部署方式** | 需要完整 MES/PLM 系统集成 | 独立数据包分发，即导即用 |

**技术实现细节：**

- 通过自研 `cad-launcher.html` 通用 CAD 启动器，动态加载 HTML 封装的 CAD 文件
- 自动注入 `resize` 自适应脚本，兼容 **HOOPS Communicator**（工业级 3D 引擎）、**Three.js** 等主流 WebGL 渲染引擎
- 在 Android 和鸿蒙端通过 `web-view` 组件实现沙盒内本地渲染，在 Web 端通过 `iframe` 隔离渲染
- 支持全屏预览、缩放、旋转等看图操作

> [!IMPORTANT]
> 这意味着在信创/国产化替代的大趋势下，本项目是目前行业内少有的在纯血鸿蒙平台上实现工业级 CAD 离线预览的方案，填补了国产操作系统在高端制造业现场数字化的空白。

### 2.2 MPM + ASP+ "数据包即工艺规程"的去中心化架构

传统制造业数字化方案以"系统为中心"——现场终端必须实时连接 MES/PLM 后台。本项目创新性地采用 **数据包驱动** 的去中心化架构：

```
ASP+ 平台配置 UI 布局 → MPM 系统编制工艺数据 → 打包导出 .srd 文件
    → USB / 内网分发 → 终端导入 → 完全离线使用
```

**这一架构的业务价值：**

1. **适配涉密网络隔离场景** — 军工、航天等行业的生产网与办公网物理隔离，`.srd` 文件可通过安全介质跨网传递
2. **数据安全可控** — 采用 AES-256-CBC 加密 + MD5 完整性校验，密钥由组织统一管理
3. **版本化分发** — SRD 包规范历经 V1（内联数据）→ V2（分离文件）→ V3（含多媒体资源）三代演进，向下兼容
4. **UI 与数据解耦** — ASP+ 平台决定界面"长什么样"，MPM 系统决定"展示什么内容"，两者独立变化互不影响

### 2.3 ASP+ 平台驱动的"UI 配置化"

不同于传统工业软件硬编码的界面，本项目的 UI 布局完全由 ASP+ 平台配置并随数据包下发：

| 配置文件 | 作用 | 示例 |
|---------|------|------|
| `ui/groups.json` | 定义 Tab 分组 | "工艺信息"分组、"工步详情"分组 |
| `ui/tabs.json` | 定义页签 | "基本信息"、"物料清单"页签 |
| `ui/components.json` | 定义组件类型与布局 | table / key-value / list / process-tree / text-block |
| `ui/icons.json` | 定义工艺树节点图标映射 | 工艺📋、工序🔧、工步⚙️ |
| `data/records.json` | 组件数据 | 各组件的实际数据内容 |

**业务意义**：不同产品线、不同工艺类型可以在 ASP+ 平台上配置不同的界面模板，无需修改客户端代码即可适配新的工艺结构。这实现了工艺现场应用的"零代码"定制。

### 2.4 全类型多媒体工艺指导

系统支持工步级别的多类型资源关联与预览：

| 资源类型 | 典型用途 | 预览能力 |
|---------|---------|---------|
| 🖼️ **图片** | 装配示意图、零件图 | 缩放、旋转、全屏预览 |
| 🎬 **视频** | 操作演示、培训视频 | 内嵌播放器 + 全屏播放 |
| 🔊 **音频** | 语音讲解、注意事项 | 自定义播放器，进度控制 |
| 📄 **PDF** | 作业指导书、标准规范 | 内嵌 PDF.js 阅读器 |
| 📐 **CAD** | 3D 模型、工程图纸 | web-view 内 WebGL 渲染 |

资源与工艺树节点通过数据库关联，支持：

- 节点切换时自动加载关联资源
- 缩略图列表 + 资源预览的双面板布局
- 全屏模式下的上一个/下一个资源导航
- 可隐藏/显示的缩略图侧边栏

### 2.5 三端同构跨平台能力

一套 UTS 代码同时编译运行于三个平台，通过条件编译实现平台差异化：

```
Android  — SQLite + java.util.zip + javax.crypto.Cipher
HarmonyOS — relationalStore + @ohos.zlib + cryptoFramework
Web      — IndexedDB + JSZip + SubtleCrypto（待完善）
```

## 三、突破的技术瓶颈

### 3.1 鸿蒙原生 API 全链路适配

HarmonyOS NEXT（纯血鸿蒙）不兼容 Android API，本项目逐一攻克了以下原生 API 适配：

| 功能模块 | 鸿蒙 API | 适配难点 |
|---------|---------|---------|
| 数据库 | `@kit.ArkData` relationalStore | RDB 的异步 API 与 Android SQLite 同步 API 差异 |
| ZIP 解压 | `@kit.BasicServicesKit` zlib | `unzip` 路径协议差异（unifile:// vs 物理路径） |
| 加解密 | `@kit.CryptoArchitectureKit` | Cipher 初始化参数格式差异 |
| 文件操作 | `uni.getFileSystemManager` | 运行时路径与开发时路径不一致 |

### 3.2 离线 CAD 的 WebView 渲染兼容

- 解决了 HTML 封装 CAD 文件在 App 端 `web-view` 组件中的安全沙盒限制
- 实现了 canvas 尺寸自适应的引擎级兼容（HOOPS / Three.js / 通用 WebGL）
- 防抖 resize 避免拖拽面板时频繁触发重绘

### 3.3 SRD 数据包的全流程处理管线

```
选择文件 → 读取为 ArrayBuffer → 尝试 AES-256-CBC 解密
  → ZIP 解压 → 解析 manifest.json → 检测版本（V1/V2/V3）
  → 分离解析 UI 配置 / 工艺数据 / 资源文件
  → 事务化写入数据库 → 资源文件复制到沙盒 → 路径映射更新
```

三个平台分别使用不同的 ZIP 和加密库，但对上层暴露统一的 `importPackage()` / `validatePackage()` API。

### 3.4 UTS 强类型语言适配

在 UTS 的严格约束下（无 `undefined`、无结构化类型、条件必须布尔值、不支持声明提升等），完成了近万行的复杂业务逻辑开发，包括递归的工艺树解析、动态组件渲染、跨平台存储抽象等。

## 六、总结

### 核心价值

本项目的核心价值可以概括为三个"首次"：

1. **首次在纯血鸿蒙平台上实现工业级 CAD 离线预览**，填补了国产操作系统在高端制造现场数字化的空白
2. **首次将 MPM 工艺系统与 ASP+ 配置平台的能力以离线数据包的形式延伸到车间终端**，实现了涉密环境下的安全数字化
3. **首次以三端同构（Android + HarmonyOS + Web）的方式覆盖车间全场景终端**，避免了多套系统的重复建设

### 瓶颈突破总结

本项目在技术层面攻克了四大核心瓶颈，为工业软件的国产化落地提供了可复用的工程经验：

- **鸿蒙生态"无人区"探路** — 在纯血鸿蒙尚无成熟工业应用先例的情况下，完成了数据库、文件系统、加解密、ZIP 解压四大基础能力的原生 API 全链路适配，验证了 HarmonyOS NEXT 承载复杂工业场景的可行性
- **离线 CAD 渲染的跨引擎兼容** — 通过自研 CAD 启动器 + resize 自适应注入的方案，在 App 端 `web-view` 的安全沙盒内实现了对 HOOPS、Three.js 等主流工业 3D 引擎的无侵入式兼容，证明了"HTML 封装 CAD + 本地 WebView"这一轻量级离线预览路线的工程可行性
- **加密数据包的全流程处理** — 在三个平台各自使用不同底层库（Java Cipher / 鸿蒙 cryptoFramework / Web SubtleCrypto）的前提下，构建了统一的"解密→解压→解析→入库→路径映射"处理管线，为 SRD 数据包规范的跨平台一致性提供了坚实保障
- **UTS 强类型工程化实践** — 在 UTS 的严格类型约束下完成了近万行复杂业务逻辑，积累了一套在强类型跨端语言中进行递归解析、动态渲染、平台抽象的最佳实践，为后续 uni-app x 生态下的工业应用开发铺平了道路

### 未来方向总结

未来的研究方向围绕 **"从查看到交互、从离线到协同、从工具到平台"** 三条主线展开：

- **从查看到交互**（近期） — 当前系统以"只读预览"为主，近期将向 3D CAD 交互（旋转/剖切/测量）、工步执行记录等"可操作"方向演进，使终端从"电子看板"升级为"数字工位"
- **从离线到协同**（中期） — 在保持离线核心能力的基础上，引入增量数据包更新、多人批注同步、执行记录回传等协同机制，实现"离线优先、按需联网"的混合架构，打通车间终端与 MPM 系统的数据闭环
- **从工具到平台**（远期） — 借助 ASP+ 平台的配置化能力和 MPM 系统的数据输出能力，将本项目从单一预览工具演进为可承载 AI 问答、AR 辅助、数字孪生等能力的 **车间数字化终端平台**，并推动 `.srd` 格式成为行业离线工艺数据交换标准

---

在信创替代和智能制造的双重趋势下，本项目不仅解决了"鸿蒙端离线看工艺"的当下痛点，更为"AI + AR + 数字孪生"的未来制造场景奠定了终端侧的基础架构。
